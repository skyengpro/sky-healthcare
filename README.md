# Sky Healthcare

SkyEngPro healthcare extensions for Frappe, ERPNext and Frappe Health (version 16).

The app ships **PharmaStock**: medicine stock and patient care for health centers, as an installable
web app (PWA) at `/pharmacy`. ERPNext Stock and Frappe Health keep the records underneath. English and
French, works offline for stock work.

| | |
|---|---|
| **Dashboard** | stock figures, 14-day activity, low stock, expiring batches, recent consultations and treatments |
| **Medicines** | list with search and filters; add a medicine with its first stock; **+ Stock** on every row |
| **Medicine page** | stock, minimum, nearest expiry, batches (oldest first), full history |
| **Give out stock** | for damaged or expired stock and authorized adjustments; always takes the earliest valid batch |
| **Medical requests** | staff ask for stock, administrators approve or reject; low stock creates requests automatically |
| **Patients** | register patients; the patient file gathers timeline, consultations, treatments, prescriptions and vital signs |
| **Consultations** | started from a patient file: symptoms, vital signs, observations, diagnosis, prescription, treatments to do |
| **Treatments** | recorded from a patient file; the medicines the treatment uses leave the stock; can be cancelled with a reason, the stock goes back |
| **Treatment types** | the cares you give and the medicines each one uses |
| **Reports** | movements, expiry, stock levels; download for Excel, print |
| **Staff** (admin) | add people, give the Staff or Administrator role, reset passwords, disable |

## How it fits together

```
PWA (Vue 3 + frappe-ui)  ->  sky_healthcare.api / .health (Python, in the site)  ->  ERPNext Stock + Frappe Health
/pharmacy                    checks the pharmacy role, one call per action
```

- **Roles:** `Pharmacy Staff` and `Pharmacy Admin`. Neither needs the ERPNext desk. The API checks the
  role, then does the work on the user's behalf, and every record keeps the real user.
- **Stock side (ERPNext):** Item (medicine), Batch (lot and expiry), Warehouse "Pharmacy", Stock Entry,
  Material Request (the app's "medical request"), Stock Ledger.
- **Care side (Frappe Health):** each medicine is also a Medication linked to its Item; patients are
  Patients; treatment types are Clinical Procedure Templates; treatments are Clinical Procedures;
  consultations are Patient Encounters; prescriptions are Medication Requests; treatments asked in a
  consultation are Service Requests. Every user created in the app also gets a Healthcare Practitioner.
- **One rule joins both:** medicine only leaves the stock for a reason, and a patient only receives
  medicine through a treatment. A finished consultation is locked. A prescription does not move stock.

## Layout of this repository

```
sky_healthcare/                  the Frappe app (Python package)
  api.py                         stock API used by the app
  health.py                      patients, treatments, consultations (Frappe Health)
  hooks.py                       install hooks, /pharmacy route, roles
  setup/install.py               roles, custom fields, notifications, warehouse, medication sync
  service_worker.py              serves the service worker at /pharmacy/sw.js
  www/pharmacy.html              the app page (generated by the build, not in git)
  public/frontend/               compiled app (generated by the build, not in git)
  public/images/                 logo
frontend/                        Vue 3 + frappe-ui source of the app (edit here)
tests/                           API and browser tests, run against a live site
docs/                            logo files
```

The compiled app is **not** in git. `package.json` at the root makes bench build it: installing the app's
node packages (`bench setup requirements --node`) runs `npm ci` in `frontend/`, and `bench build` runs
`npm run build`. The server therefore needs **Node 20 or newer** (the CI uses 24).

## Requirements

- Frappe, ERPNext and Frappe Health (`healthcare`) **version 16**, Python 3.14.
- A company must exist (ERPNext setup wizard done) when the app is installed. Otherwise create the store
  afterwards:

  ```bash
  bench --site <site> execute sky_healthcare.setup.install.create_warehouse
  ```

- If the company uses perpetual inventory it needs a *Default Inventory Account* (Company settings),
  or stock postings fail. The installer warns about this and does not change accounting settings.

## Install on a site

```bash
bench get-app erpnext --branch version-16
bench get-app healthcare --branch version-16
bench get-app https://github.com/skyengpro/sky-healthcare --branch <branch>
bench new-site <site> --admin-password <password>
bench --site <site> install-app erpnext healthcare sky_healthcare
```

Node packages are installed by `bench get-app` (or `bench setup requirements --node`). If the screens are missing at `/pharmacy`, build them:
`bench build --app sky_healthcare`. Run the setup wizard in the browser once before using the app. Then open `https://<site>/pharmacy`.

Create the first users from the desk (**User**, role `Pharmacy Admin` or `Pharmacy Staff`). Administrators
then add the rest of the team on the **Staff** page of the app.

On Frappe Cloud / Press: add this repository under the bench's **Apps** next to ERPNext and Healthcare,
deploy, then install the app on the site.

## Develop

```bash
cd frontend
npm ci
npm run dev       # http://localhost:8090/pharmacy, API proxied to SITE_URL (default http://localhost:8088)
npm run build     # writes sky_healthcare/public/frontend and sky_healthcare/www/pharmacy.html (not committed)
npm run icons     # re-renders the PWA icons from public/logo-mark.svg
```

Translations: English is in the code, French in `frontend/src/fr.js`.

Code style: `pre-commit install` in the repository. Python is checked with ruff (tabs, 110 columns).

## Tests

The tests run against a live site with the app installed and two users, a Pharmacy Staff and a
Pharmacy Admin. They create their own test data (names start with `ZZ`, `E2E` or `Care`) and leave it
in place, so use a development site.

```bash
# API: stock in and out, earliest expiry first, refusals, duplicate protection, requests, permissions
python3 tests/api_smoke.py <site-url> <staff-email> <staff-pw> <admin-email> <admin-pw>

# Frappe Health: patients, treatments and their stock, cancelling, doctors, consultations
python3 tests/health_smoke.py <site-url> <staff-email> <staff-pw> [<admin-email> <admin-pw>]

# Browser, headless Chrome (needs puppeteer-core): staff and admin journeys, PWA install,
# offline use and sync, phone and French
node tests/e2e.mjs <site-url> <staff-email> <staff-pw> <admin-email> <admin-pw> [screenshot-dir]

# Care flow through the UI: medicine, patient, treatment type, treatments, cancel, consultation, dashboard
node tests/care_e2e.mjs <site-url> <staff-email> <staff-pw> <admin-email> <admin-pw> [screenshot-dir]
```

`tests/e2e.mjs` expects the staff user's full name to be "Grace Mbarga".
